Project 05

StockValue.Ai

A financial analysis platform, designed and shipped solo with AI-native tools.

Role Solo Designer & Builder Built 2025–2026 Live at stockvalueai.netlify.app

Eight analysis modules — DCF, Key Metrics, Historical Charts, Fear Gauge, Price & EPS, CAPM & Alpha, Insider Trades, News — from a single stock symbol input.

Problem

Serious financial analysis tools — DCF models, risk metrics — are either too shallow for real investors or too dense for anyone else. I wanted to test what one person could now ship solo with AI-assisted tooling, using a real, useful product as the proof.

HCI Approach

Designed an information architecture that holds both audiences: eight analysis modules behind one stock-symbol input, editable assumptions for people who want to test their own thesis, sensible defaults for everyone else. Trust signals — last-updated timestamps, data source labels, fair-value-vs.-current-price framing — do the work of making the output feel credible.

Used Bolt.new and Claude Opus as a build partner: defining requirements precisely, reviewing every generated line, and directing the build rather than prompting blind.

User Flow
Enter a ticker → View DCF, risk & sentiment modules → Adjust WACC/growth assumptions → Compare fair value to market price
Outcome

A live, working tool with eight functional modules, integrated with real-time market data, that I and others use to make actual investment decisions. Proof that this category of product — five years ago, a small team and six figures of investment — is now shippable solo, in spare time, in months.

Reflection

Should have written a formal design system before generating screens. It held together because I was the only reviewer — it's the piece of this workflow I'm now formalizing for client work, so a solo AI-native build stays as consistent as a team-built one.

Why this project is on the site

The other four case studies show how I run strategy, research, and design at the scale of a corporate team. StockValue.Ai shows the other half: that one person, with the right product and design foundation, can carry a project through to a live, working build using AI-native tools instead of a full engineering team.

I didn't prompt blindly. I structured the information architecture, defined the financial logic, and designed the trust signals a serious user would need before Bolt.new and Claude Opus generated a line of code. An AI tool needs a clear spec and clear design intent to produce something coherent — without that scaffolding it produces a demo, not a product.

Depth without intimidation

A serious financial analysis tool has to show its work — DCF logic, WACC and growth assumptions, data sources — or a serious investor won't trust the output. But most people who'd benefit from a DCF valuation have never built one and don't want a wall of formulas. The architecture holds both: eight modules organized behind a single symbol input, editable assumptions surfaced for people who want them, sensible defaults for everyone else.

Bolt.new as a development partner, not a shortcut

I used Bolt.new, powered by Claude Opus, as the engineering partner — reviewing every piece of generated code, debugging the Alpha Vantage API integration when the model's first pass missed edge cases, iterating on UI in conversation instead of a sprint cycle. The judgment calls — when to trust generated code, when to rewrite it, how to keep the app maintainable as it grew — were mine to make.

What I'd do differently

I'd invest earlier in a written design system inside the AI tool's context — a component and pattern reference the way a Figma library provides a design team — rather than letting the visual language emerge screen by screen.
